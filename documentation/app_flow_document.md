# App Flow Document

## Onboarding and Sign-In/Sign-Up

When a new user visits the application, they first land on a clean landing page that introduces the AI-Powered Schedule Audit Assistant and offers options to sign up or sign in. The landing page features two prominent buttons labeled “Sign Up” and “Sign In.” If the user chooses to sign up, they are taken to a registration form where they can create an account by entering their email address, choosing a secure password, and confirming the password. Alternatively, the user may click a social login button to sign up using their Google account, in which case they authorize the app to access their basic profile information and are logged in immediately. After completing the sign-up fields, the user receives a confirmation email to verify their address. Once verification is complete, they can return to the app and sign in.

If the user already has an account, clicking the “Sign In” button directs them to the login page. Here they enter their email and password or choose the social login option if they previously signed up with Google. After successful authentication, they are redirected to the main dashboard. A “Forgot Password” link on the sign-in form allows users who cannot remember their password to request a reset email. By clicking that link, they enter their email address and receive an email with a secure, time-limited link. Clicking the link opens a password reset page where they set a new password, confirm it, and are then automatically signed in. At any point, the user can sign out by clicking the profile icon in the header and choosing “Sign Out,” which ends their session and brings them back to the landing page.

## Main Dashboard or Home Page

After signing in, the user lands on the main dashboard at the `/dashboard` route. The screen is divided into a sidebar on the left, a header across the top, and a main content area. The sidebar lists navigation links labeled “Chat Assistant,” “Calendar View,” and “Settings.” The header displays the user’s name or email, a theme toggle switch for light and dark modes, and a profile icon for account options. In the main content area, the default view is the Chat Assistant interface, where the user sees a text input at the bottom and a scrollable chat window above. A placeholder message invites the user to describe their schedule. To move to the calendar page, the user clicks “Calendar View” in the sidebar. To adjust account preferences, they click “Settings.” This clear layout ensures the user always knows where they are and how to reach other parts of the application.

## Detailed Feature Flows and Page Transitions

When the user interacts with the Chat Assistant, they type a natural-language description of their day into the input field and press Enter. The front-end component submits the text to an API endpoint at `/api/chat`, which uses the Vercel AI SDK to parse the prompt. The AI responds in real time, streaming messages back to the chat interface. If the message contains schedule details, the AI’s structured output is validated against a predefined schema and saved in the database as one or more schedule events. Each time a new message arrives, it appears as a chat bubble with a timestamp.

If the user clicks the “Calendar View” link, the app navigates to `/dashboard/calendar`. On this page, a calendar component fetches all saved events for the logged-in user from the PostgreSQL database via Drizzle ORM. The calendar displays events in daily, weekly, or monthly layouts. Above the calendar, a simple filter bar lets the user pick a date range or event category, and the view updates automatically. Clicking on an event in the calendar opens a modal showing event details and offers an “Edit” button. When the user edits the title or times and clicks “Save,” the updated data is sent to an API route at `/api/events/[id]` using a PUT request. The calendar then refreshes to reflect the changes.

From either the chat or calendar page, the user can click the logo in the header to be taken back to the default Chat Assistant. Navigating between pages preserves chat history and calendar entries without requiring additional logins or data refreshes beyond what each page normally fetches.

## Settings and Account Management

In the Settings page at `/settings`, the user can update personal information, including their display name and email address. A simple form displays the current values and allows inline editing. To change the password, the user clicks a “Change Password” link that expands a section with fields for the current password, new password, and confirmation. Submitting the form sends data to `/api/account/update` and returns success or validation errors. Below, a section labeled “Theme” lets the user switch between light, dark, or system default mode. Changes take effect immediately and persist across sessions.

If billing or subscription support is added later, it would appear as another section on this page. The user would see their current plan, a list of available plans, pricing details, and a “Change Plan” button. Selecting a new plan would lead to a payment form powered by the chosen payment processor, and upon a successful transaction, the subscription state in the database would update accordingly. After completing any updates, the user clicks “Save Settings” and is brought back to the main dashboard.

## Error States and Alternate Paths

If the user enters invalid credentials on the sign-in page, an inline error message appears below the input fields, explaining that the email or password is incorrect. On the registration page, missing or mismatched password confirmations trigger validation messages next to the relevant fields. When a user attempts to reset the password, expired or invalid reset tokens result in an error page with a clear explanation and a link to request a new reset email.

During normal use, if the app loses connectivity while the user is chatting, a notification bar appears at the top of the chat component stating that the connection is lost. The chat input is temporarily disabled until the connection is restored, at which point the user can retry sending messages. If the `/api/chat` endpoint returns an error, the chat window displays a user-friendly message suggesting to try again later. Similarly, if the calendar fails to load events, the page shows a short message and a “Retry” button that re-fetches data. Restricted actions, such as trying to view the calendar while logged out, redirect the user to the sign-in page with an explanatory notice.

## Conclusion and Overall App Journey

A user begins by landing on the app’s welcome screen, signs up using email or Google, and verifies their account. Once authenticated, they arrive at the dashboard showing the chat assistant. There, they describe schedule details naturally and see an AI-powered response that also stores events automatically. They navigate to the calendar to visualize and edit events, then return to chat for further adjustments. In Settings, they manage personal details, change their password, and toggle the theme. Throughout their session, the app handles invalid inputs, lost connections, and authorization errors gracefully, always guiding the user back to a smooth workflow. This end-to-end journey empowers users to audit and manage their time effectively through a simple chat interface and a visually rich calendar view.
